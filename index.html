Кейс 1 · ИИ-контроль качества продаж

Разбор каждой встречи менеджера с клиентом моделью по чек-листу

Отдел продаж проводит около 300 диагностических Zoom-встреч в месяц. Руководитель физически может послушать единицы. Внешний подрядчик по контролю качества стоил дорого и давал оценки без доказательств.

Что собрал

  • Конвейер: запись Zoom → скачивание по ссылке → транскрибация Deepgram nova-3 с диаризацией → обезличивание → разбор LLM → дашборд.
  • Чек-лист из 15 обязательных элементов встречи. На каждый элемент модель отвечает «спрошено / присутствует», объясняет почему и приводит цитату. Код находит цитату в расшифровке и ставит тайминг «м:сс».
  • Речевые метрики из диаризации: доля речи менеджера, длина монологов, темп, паузы, вопросов в минуту. Норма речи менеджера 45–60 %.
  • Формула балла: цель встречи 30 + элементы 30 + этапы 25 + речь 15, красная зона перекрывает всё. Лента вердиктов по риску для руководителя, вкладка каждого менеджера с его личным скриптом.
  • Обезличивание: имена и персональные данные заменяются перед отправкой модели, в ответе подставляются обратно.
  • Сверка четырёх моделей на двух эталонных встречах против ручной оценки. Выбор: Claude Sonnet на поток, Claude Opus на спорные. Стоимость каждого разбора пишется в отчёт из usage API.
  • Раннер: GitHub Actions, четыре сценария (пакет по листу, одна запись, диаризация, пересчёт). Смена провайдера моделей за один день, когда прежний ограничил аккаунт.

Кейс 2 · ИИ-ассистент продаж в чате на сайте

Чат на сайте, который квалифицирует лида и ведёт переписку в CRM в обе стороны

Лиды с сайта попадали в «Неразобранное» CRM без источника, менеджеры отвечали с задержкой, ночью никто не отвечал. Нужен был чат, который сам начинает разговор, отсеивает нецелевых и отдаёт менеджеру тёплый диалог.

Что собрал

  • Виджет одним сниппетом на любой сайт, включая Tilda. Бэкенд на Cloudflare Pages Functions + D1, деплой из GitHub Actions.
  • Двусторонняя интеграция с amoCRM через API чатов (amojo): первое сообщение создаёт сделку сразу в нужной воронке с источником, UTM и реферером, минуя «Неразобранное». Дедупликация по телефону: активная сделка есть, новую не плодим.
  • Бот-квалификатор на LLM, неотличимый от менеджера: собирает команду, оборот, роль, нишу; нецелевых мягко отсеивает и закрывает сделку автоматически. Защита от инъекций и провокаций, дебаунс, «печатает…», тайминги как у человека.
  • Диалог как конечный автомат: приветствие → касания → квалификация → передача. Ночная ветка, лесенка цены, четыре разных захода за номером. Стресс-тест на 50 диалогах без нарушений правил.
  • Мультиагентный разбор живых диалогов: шесть ролей-критиков (судья правил, уход клиента, голос бота, сверка с CRM, парсер ответов) и агент-скептик, который отбрасывает ложные находки.
  • Статистика: воронка по диалогам, медианы ответа по менеджерам, источники с раскрытием до страницы и переписки.

Кейс 3 · Центр управления компанией

Витрина метрик для собственника и руководителей вместо десятка таблиц

Цифры компании жили в Google-таблицах, CRM, АТС и Метрике. Собственник хотел один экран с планом и фактом, а подрядчики оценивали такую систему в 150 000 ₽ в месяц.

Что собрал

  • Cloudflare Pages + Workers + D1 + KV: сборщик ночью тянет CRM, звонки АТС, Яндекс Метрику и таблицы в базу, страницы читают API.
  • Воронки план/факт с прогнозом на месяц, конверсии между ступенями, срезы по источникам, тегам и UTM, звонки по менеджерам первой линии.
  • Права по разделам и ролям, вход через Telegram, разделы для продаж, маркетинга, найма и настроек.
  • Чат с ИИ по цифрам компании и генерация пользовательских экранов моделью по запросу.
  • Подготовка диагноста к встрече: по переходу сделки на этап «встреча подтверждена» модель с веб-поиском собирает досье клиента в четыре шага. Разбор встречи после: лояльность, ключ к следующему контакту.
  • Инструменты для команды внутри: генератор ссылок для блогеров, карта воронок для менеджеров, дашборд проектов и утренний бриф в Telegram.

Кейс 4 · Автоматизация CRM без платной платформы

Перенос всей автоматизации с n8n на GitHub Actions и скрипты, плюс первые записи в CRM роботом

Компания платила за n8n, воркфлоу ломались молча, а править их мог только один человек. Нужно было убрать платформу, не потеряв ни одного отчёта, и начать безопасно менять данные в CRM автоматически.

Что собрал

  • Около 10 ночных конвейеров на Python в GitHub Actions: сделки и контакты, звонки АТС, телефония по отделам, события по менеджерам, активность базы, транскрибация Zoom. Отчёты и ошибки в Telegram.
  • Автозакрытие зависших сделок: 27 дней без движения → задача ответственному, 30 дней → закрытие с причиной. Защиты: лимит на запуск, список исключений, тег «не автозакрывать», сухой прогон при ручном старте.
  • «Сторож» потери лидов: вебхук CRM ловит перенос сделки в чужую воронку, пишет в Telegram, откат по кнопке. Собран и выведен в бой за один день.
  • Прокладка между чат-ботом и CRM: решает, создавать ли сделку, по правилам воронок и поиску по последним 10 цифрам телефона.
  • Дедупликация базы контактов: безопасные группы объединены скриптом через внутренний API, спорные оставлены человеку.
  • Инциденты: восстановление 1 621 лида после срезанной ссылки источника; резервный Telegram-бот за день, когда внешняя платформа чат-ботов легла.
